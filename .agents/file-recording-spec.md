# 文件记录规范

> 本文件从 `AGENTS.md` 拆分而来，作为历史故事 Agent 的**文件记录与落盘约定**专项规范，采用独立顶层编号 §1–§6。
>
> **跨文件引用约定**：AGENTS.md 其他章节引用本文件时一律写作「**文件记录规范 §N**」（如「文件记录规范 §1」），以避免与 AGENTS.md 自身 §1–§4 产生编号歧义；本文件内部互引直接写「§N」即可。

## 1. 文件路径与写入规范

| 路径 | 用途 |
|------|------|
| `logs/eras/` | 按朝代拆分的故事图谱，每朝代一个文件（`00_sanhuang_wudi.md`、`01_xia.md`） |
| `logs/progress.md` | 进度跟踪，仅记录当前状态和概览 |
| `logs/contents/<era_dir>/` | 按朝代划分的故事目录，目录名与 `eras/` 文件名前缀对应（`00_sanhuang_wudi/`、`01_xia/`） |
| `logs/contents/<era_dir>/<story_id>.md` | 每故事一个独立文件，文件名为故事 id（`xia_14.md`、`sanhuang_05.md`），存储该篇故事原文（含背景/正文/备注） |

**定位与写入规则**：

- `<era_dir>` 为当前故事所属朝代目录名，与 `eras/` 文件名前缀一致；进入新时代时目录不存在须先创建
- `<id>` 为故事唯一标识，格式 `{era_code}_{number}`（如 `xia_22`、`sanhuang_05`），与 `eras/*.md` 中的故事编号对应
- 每故事独占一文件，文件名即 id，严禁多故事共用
- 文件不存在：创建并写入
- 文件已存在：读取其 YAML `id` 字段——与当前故事 id 一致则覆盖写入；不一致则报错（表明文件名与内容错位，须人工处置）
- 每个故事必须包含 YAML 元数据头（见 §4）

## 2. eras/*.md 结构模板

```markdown
# 时代名称 - 故事图谱

## 时代谱系

[简洁的时代传承描述]

| 掌权阶段 | 统治者/权力中心 | 时间范围（约） | 继承关系 | 备注 | 对应故事 |
|---------|----------------|---------------|---------|------|---------|
| 1 | 黄帝 | 约前 2717-前 2599 年 | — | 开国 | #1、#2 |
| 2 | 颛顼 | 约前 2514-前 2437 年 | 黄帝之孙，昌意之子 | 孙继祖 | #3 |
| 3 | 帝喾 | 约前 2436-前 2367 年 | 颛顼之侄，蟜极之子 | 侄继叔 | #4（合篇） |
| 4 | 尧 | 约前 2357-前 2255 年 | 帝喾之子，放勋 | 子继父 | #4 |
| 5 | 舜 | 约前 2255-前 2205 年 | 尧之婿，瞽叟之子 | 禅让 | #5 |
| ... | ... | ... | ... | ... | ... |

**继承关系说明**：记录血缘（「某之子」「某之孙」）或政治（「禅让」「篡位」「拥立」）关系，优先血缘；两者并存须均标注（「帝喾之子，禅让」）；史料分歧以主流为主，分歧在备注或正文中说明。

**「对应故事」列规格**：
- 每位掌权者必须至少有一个编号（不允许空值），确保时间轴连续；允许多值用「、」分隔
- **主篇**（掌权者为故事主体）：编号无需额外标注
- **合篇**（单一政权时期多位掌权者共一篇群像）：编号后加 `（合篇）`
- **专篇承接**（多势力并立时代，分势力分期专篇内按序点名承接某掌权者）：编号后加 `（专篇承接）` 或 `（承接）`；同专篇一般覆盖多位同期同势力掌权者，主角之外均按承接处理
- **互斥使用**：「合篇」与「专篇承接」按时代类型二选一，同一图谱内不混用——单一政权用「合篇」，多势力并立用「专篇承接」
- 同一篇故事可同时作为某掌权者主篇、其他掌权者合篇/承接
- 仅当掌权者为传说性或存在性存疑时填 `⊘`，并在相邻故事备注说明（⊘ 含义详见 §5）

|---|------|--------|------|------|
| A+1 | [分期名]的[势力名]——[该期该势力主题] | 高 | 对比 | ⏳ |

### 二、[下一分期]……

### N、里程碑事件篇

### N+1、通论补充题材

### N+2、时代收束篇

**延伸拓展候选说明**：
- 不占正式编号，不参与进度统计，无 ✅/⏳ 状态
- 用户确认升入正式列表时，分配新编号并迁入对应骨架；同步更新受影响掌权者「对应故事」列
- 用户明确否决的候选可移出本板块或追加「否决」标注

---

- 状态说明：✅ 已完成 | ⏳ 待输出（故事列表状态仅此两种；⊘ 专属谱系表标注存疑掌权者，详见 §5）
- 「抓手」列简注该篇对应的学史方法（考证/关联/对比），多种用「、」分隔
```

## 4. contents/<era_dir>/<id>.md 元数据约定

每故事文件必须包含 YAML 元数据头：

```markdown
---
id: story_id
era: era_code
section: 掌权阶段名称
title: 故事标题
---

# 故事标题

## 故事背景
...
```

**字段与约束**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 故事唯一标识，格式 `{era}_{number}`（`xia_14`、`sanhuang_05`）；同时作为文件名 |
| `era` | 是 | 时代代码（`xia`、`shang`、`zhou`、`sanhuang` 等） |
| `section` | 是 | 篇所属类别与位置。篇型填法：掌权阶段篇如 `杼时期`、`禹时期`；分期导论篇如 `战国早期·导论`；分势力分期专篇如 `战国早期·魏`、`三国三分期·吴`；里程碑事件篇如 `长平之战`、`赤壁之战`；通论补充篇按子维度——全时代横截类 `战国·全时代·铁器牛耕`、`三国·全时代·九品中正制`，分势力专项类 `战国·楚专项·楚辞`、`三国·魏专项·建安文学`，跨势力专题类 `战国·跨势力专题·百家争鸣`、`战国·跨势力专题·孟子`；时代收束篇如 `战国·终章`；合篇跨多阶段时以主篇阶段为主值并追小注（`太戊时期（含沃丁—雍己）`） |
| `title` | 是 | 故事完整标题，与正文一级标题一致 |

- 元数据头必须用 `---` 包围，不得省略
- `id` 必须与 `eras/*.md` 中的故事编号对应
- 每故事独占一文件，文件名即 `id`（`xia_14.md`），不存在多故事共用

## 5. 状态符号约定

| 符号 | 含义 |
|------|------|
| ✅ | 已完成 |
| ⏳ | 待输出 |
| 🔄 | 进行中（仅用于 `progress.md` 时代级进度统计） |
| ⊘ | 存疑略过（仅用于传说性或存在性存疑的掌权者，须在相邻故事备注说明原因） |

## 6. 文件命名规范

- 时代文件：`eras/XX_name.md`（XX 为序号，从 00 开始）
- 故事目录：`contents/XX_name/`（与 `eras/` 文件名前缀一致，如 `01_xia/`、`02_shang/`）
- 故事文件：`contents/XX_name/{era}_{number}.md`（文件名即故事 id，如 `01_xia/xia_14.md`、`00_sanhuang_wudi/sanhuang_05.md`）
- 进度文件：`progress.md`
