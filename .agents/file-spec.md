## 1 logs/eras/*.md 结构模板

### 1.1 形态约束（正史/文学通用）

- **头部**：1 段引言（blockquote），含图谱说明与正史参照（文学线须标注「并行叙事线·文学线」并链接正史线文件）
- **章节正文**：按需组织「传承图谱 / 故事列表 / 备选题库」三大块
- **流程标注分流**：故事级状态符号（⏳/✅）属于图谱内容，保留在时代文件故事列表中；其余执行痕迹（已确认、修订日期、用户裁决标记等）一律写入 `logs/progress.md`，**不得混入时代文件正文**

### 1.2 模板


### 1.3 字段填写说明

以下说明对应模板中各字段的填写规则，不写入输出文件。

**继承关系**：
- 记录血缘（「某之子/孙」）或政治（「禅让/篡位/拥立」）关系，优先血缘
- 并存须均标注（「帝喾之子，禅让」）
- 史料分歧以主流为主，分歧在备注说明

**「时间范围·时长」列格式**：
- 可计算：`约前XXX-前XXX年（约N年）`
- 时长不详：`不详（？年）`或 `约某时期（？年）`
- 未即位：`未即位`（不标时长）

**「对应故事」列规格**：
- 每位掌权者至少一个编号（不允许空值），多值用「、」分隔
- **主篇**（掌权者为主体）：无需额外标注
- **群像篇**（单一政权时期多人共一篇群像）：编号后加 `（群像）`
- **附篇承接**（多势力并立时代，势力展开篇按序点名承接某掌权者）：编号后加 `（承接）`
- **互斥**：单一政权用「群像篇」，多势力并立用「附篇承接」，同一图谱不混用
- 同一篇可同时作为某人主篇、他人群像/承接
- 传说性或存在性存疑者填 `⊘`，并在相邻故事文件的备注中说明

**候补故事选题说明**（规则定义见 [narrative.md §2.4](narrative.md)）：
- 不占正式编号，不计进度，无 ✅/⏳
- 升入正式列表时分配新编号并迁入对应位置，同步更新图谱「对应故事」列
- 用户否决者可移出或加「否决」标注

**状态行说明**：
- 故事状态：✅ 已完成 | ⏳ 待输出
- 图谱特殊标注：⊘ 存疑掌权者（仅用于 `eras/*.md` 图谱）

## 2 progress.md 结构模板

**约束**：

- 必备 3 节：`当前状态` / `各时代进度` / `当前进度`
- `当前状态` 表固定 4 行：当前时代 / 已完成故事总数 / 跳过故事数 / 存疑掌权者数
- `各时代进度` 表的状态列用 `已完成 (m/n)` 或 `进行中 (m/n)` 表示
- **手动维护**：进度表与状态数字在每次故事状态变更（⏳→✅）时由 AI 同步更新；状态数字应以 `eras/*.md` 故事列表的 ✅/⏳ 统计为准（用户裁决后由 AI 改写）

```markdown
# 历史故事进度

## 当前状态

| 项目 | 状态 |
|------|------|
| 当前时代 | 时代名称 |
| 已完成故事总数 | N |
| 跳过故事数 | N |
| 存疑掌权者数 | N |

---

## 各时代进度

| 时代 | 状态 | 进度 |
|------|------|------|
| 时代A | 已完成 (m/m) | m/m |
| 时代B | 进行中 (m/n) | m/n |

---

## 当前进度

- **时代**：时代名称
- **当前故事**：故事名称（状态）
- **下一个故事**：故事名称

---

*进度概览与执行指针；数据由 `eras/*.md` 与 `contents/<era_dir>/*.md` 汇总*
```

## 3 logs/contents/<era_dir>/<id>.md 元数据约定

每故事文件必须包含 YAML 元数据头：

```markdown
---
id: story_id
era: era_code
section: 掌权阶段名称
title: 故事标题
---

# 故事标题

## 故事背景
...
```

**字段与约束**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 故事唯一标识，格式 `{标识符}_{number}`，与文件名及 `logs/eras/*.md` 故事列表「#」列严格对应 |
| `era` | 是 | 时代代码/作品名，见 [AGENTS.md §5](../AGENTS.md)。正史线如 `xia`、`sanhuangwudi`；文学线如 `fengshen` |
| `section` | 是 | 篇目焦点与位置，见下 |
| `title` | 是 | 完整标题，与正文一级标题一致 |

**`section` 取值**：应反映本篇焦点 + 在时代中的位置，格式自由——掌权阶段类（`杼时期`）、势力展开类（`战国早期·魏`）、重大事件类（`长平之战`）、人物传记类（`商鞅列传`）、制度兴亡类（`府兵制兴衰`）、思想文化类（`百家争鸣`）、综合通论类（`战国·全时代·铁器牛耕`）。

**结构性必备标记**（必须出现于每个分卷 / 整个时代）：

- **分卷导论**（每个分卷一篇）——`[分卷名]·导论`，例：`战国早期·导论`
- **时代终章**（整个时代一篇）——`[时代]·终章`，例：`战国·终章`

**特殊情形**：

- 群像篇跨多阶段：主篇阶段为主值并追小注，如 `太戊时期（含沃丁·雍己）`
- 文学线对应：叙事阶段类 / 分卷导论 / 线索·人物展开类

允许按实际焦点自由命名，但须同时包含「焦点类型」与「时代 / 阶段位置」两个要素，避免只写人名或只写事件名；语义清晰即可。

**约束**：

- 元数据头必须用 `---` 包围，不得省略
- `id` 必须与 `logs/eras/*.md` 故事编号对应
- 每故事独占一文件，文件名即 `id`

## 4 状态符号约定

**故事级状态**（仅两种原子态，由执行步骤自动触发转换）：

| 符号 | 含义 | 首次写入时机 | 转换触发 |
|------|------|-------------|---------|
| ⏳ | 未完成 | [AGENTS.md §4.3](../AGENTS.md) 故事列表经用户确认后 | — |
| ✅ | 已完成 | [AGENTS.md §4.5](../AGENTS.md) 审查校对所有 Checklist 项通过后 | ⏳ → ✅ |

> [说明] **时代级完成度**由故事级状态自动推导——一个时代全部故事为 ✅ 即为已完成，无需独立符号。

**图谱字段标注**（非状态，与 ✅/⏳ 正交）：

- **⊘** —— 传说性或存在性存疑的掌权者，须在相邻故事备注说明。仅用于 `eras/*.md` 图谱，不参与状态统计。

---

## 5 文件写入规则

- **文件不存在**：创建并写入
- **文件已存在**：读 YAML `id`——与当前一致则覆盖；不一致则报错（文件名与内容错位，须人工处置）
- **必须包含 YAML 元数据头**（§3）
- **写入前确认目录存在**；不存在则先创建

## 6 并行叙事线文件格式

> 命名规则见 [AGENTS.md §5](../AGENTS.md)（并行文学线段），本节说明文件结构层面的差异。

### 6.1 底本图谱结构

文学线图谱以**原著分卷**为架构，输出至 `logs/eras/{编号}_{作品名}.md`，**5 字段表，「对应故事」列必须填满编号**：

| 分卷名 | 起始·终止章回 | 核心事件 | 核心人物 | 对应故事 |
|---------|--------------|---------|---------|---------|
| [段名] | 第X回 — 第Y回 | [中心事件] | [主要人物] | #1、#2 |
| ... | ... | ... | ... | ... |

**「起始·终止章回」列格式**：原著回目范围，精确到回（如「第一回 — 第十五回」）；原著回目以主流版本为准，版本异文在备注说明。

**「对应故事」列规格**：
- 每段至少一个编号（不允许空值），多值用「、」分隔
- 同一段可作为多篇故事的核心或承接
- 原著叙述稀薄者如实登记，不跳过

### 6.2 文学线时代文件差异

- 引言中标注「并行叙事线·文学线」并链接正史线对应时代文件
- 图谱按本节 §6.1 格式（与正史线的掌权者传承表不同）
- 进度条目在 `logs/progress.md` 独立列出，不计入正史进度

## 7 临时校对文档

`writing.md §8.3` 要求校对时维护临时校对进程文档，其规范如下。

### 7.1 路径与命名

```
logs/contents/<era_dir>/<id>.proof.md
```

其中 `<era_dir>` 与 `<id>` 与对应故事文件一致。

### 7.2 内容格式

按 `writing.md §8.3` Checklist 顺序记录每项校对结果：

- `✅` 通过
- `❌` 不通过 → 附修订记录
- `N/A` + 原因

### 7.3 生命周期

- 校对开始时创建；
- 全部 Checklist 项通过后删除；
- 转入 [AGENTS.md §4.5](../AGENTS.md) 更新进度。
